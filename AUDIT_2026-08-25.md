## 🟠 MAJEUR

### Sécurité réseau
- [ ] **M1 — SSRF par redirections.** La porte anti-SSRF (`host_resolves_private`)
      ne s'applique qu'à l'URL initiale ; `http_get` (web_crawl.rs:226-254) et
      reqwest `Policy::limited(5)` (:205) suivent jusqu'à 5 hops **sans re-check**.
      Une page publique → `Location: http://169.254.169.254/…` est fetchée,
      indexée, exportable. *Fix* : validation par hop (boucle std) +
      `Policy::custom` rejetant les IP privées (feature web).
- [ ] **M2 — SSRF par userinfo.** Avec feature `web` : `http://evil.com@127.0.0.1:8080/`
      — `parse_url` maison garde host=`evil.com@127.0.0.1` → résolution DNS échoue →
      gate laisse passer ; reqwest (WHATWG) strip le userinfo et dial 127.0.0.1.
      Deux parseurs divergents = primitive SSRF. *Fix* : rejeter toute authority
      contenant `@`, ou vérifier l'adresse socket à la connexion.
- [ ] **M3 — Panics distants → livelock du crawler.** Trois vecteurs déclenchables
      par contenu hostile, tous reproduits : (a) titre : offset trouvé dans
      `raw.to_lowercase()` slicé sur `raw` — les mappings Unicode changent la
      longueur d'octets ('ẞ','İ') → panic char boundary (web_crawl.rs:357-363) ;
      (b) `unchunk` : taille hex sans CRLF final → `start>len` slice panic
      (:330-348, aussi emprunté par RobotsTxt::load) ; (c) `extract_url` fenêtre
      fixe 600 o non alignée (:1274). Un panic saute le `fetch_sub(in_flight)` du
      worker (:945-947) → condition de sortie `in_flight==0` jamais atteinte →
      `crawl()` hang à vie (join discrètement :884). *Fix* : catch_unwind + garde
      RAII sur in_flight ; corriger les 3 slices (réutiliser `dechunk` de llm.rs).
- [ ] **M4 — Lecture corps complet avant cap (feature web).** `resp.bytes()`
      bufferise TOUT avant `len()>max_bytes` (:210-219) → OOM remote. Le client
      std, lui, borne en cours de lecture (:285). *Fix* : streamer via `chunk()`.

### Boucle DGM (santé du flywheel)
- [ ] **M5 — Comptes de tests fabricables par le candidat.** `parse_test_counts`
      (dgm.rs:1210) somme TOUTES les lignes `test result:` de stdout ; un test peut
      écrire directement sur le vrai stdout (échappe `set_output_capture`) et
      injecter « 1000000 passed ». Gagne la barrière lexicographique, exempté de
      `min_score_gain`, archivé puis — avec `--promote` — **vit dans l'arbre** et
      gonfle toutes les baselines futures. Idem bench : `RSI_BENCH_SCORE=1e300`
      auto-déclaré, jamais corroboré. *Fix* : canal de confiance (`--format json`
      validé, ou reconciliation `--list`, ou cap `baseline+Δ déclaré`) ; bench =
      temps mur mesuré côté évaluateur.
- [ ] **M6 — Lineage DGM fictif.** `evaluate_candidate` snapshotte la racine live
      et n'applique QUE le patch du candidat (dgm.rs:1911-1920) — les enfants
      n'héritent jamais des patches parents, contrairement à `generation`,
      `select_parent` et la doc Darwin-Gödel. Effets : FIND parent-dépendants
      échouent, améliorations < parent mais > root rejetées, patches identiques
      ré-acceptés (variant_id inclut `seq`), trajectoires exportées mal étiquetées.
      La promotion reste sûre (état évalué == état promu) mais par accident.
      *Fix* : replay des ancêtres dans le snapshot, OU assumer root-only
      (parent=root toujours, generation supprimé) + dédup par hash de patch.

### Chaînes de preuve & pipelines bornés
- [ ] **M7 — Tests invisibles en CI.** `cargo test --locked` (ci.yml:60,68) lancé
      à la racine SANS `--workspace` n'exécute que le crate racine : **85 tests**
      de forge/ccos/cogno-* ne tournent jamais en CI (clippy les linthe seulement).
      Aucun `cargo test --all-features` non plus (le clippy all-features prouve la
      compilation, pas le comportement de `web`/`forge`/`ccos`). *Fix* :
      `cargo test --locked --workspace` + une patte all-features.
- [ ] **M8 — Troncature de chaîne indétectable.** `HashChainLog::verify`
      (audit.rs:193-204) et `EventLog::verify_integrity` marchent depuis GENESIS :
      tout **préfixe** est une chaîne valide — supprimer les k derniers événements
      (ou exporter via `to_ccos_json`) vérifie `true`, HMAC ou pas. L'export
      forensique peut thus être amputé silencieusement. *Fix* : ancre externe
      `(head_hash, len)` (checkpoint/manifeste d'export), paramètre attendu de verify.
- [ ] **M9 — join() non borné après kill.** `evaluation_pipeline.execute_step`
      tue l'enfant au timeout puis `stdout_thread.join()` sans deadline
      (:334-339) ; un petit-fils héritant les pipes (cas cargo test hung) fait
      hanguer le pipeline « bounded » et donc la qualification release. Contraste :
      paper_science.rs:200-227 détache + `recv_timeout`. *Fix* : process group +
      killpg, ou joins avec deadline (pattern channel).

### Robustesse CLI
- [ ] **M10 — Overflow u32 sur input.** `np + 8192` (rsi_ascend.rs:177 ;
      rsi_dgm.rs:199,324 ; rsi_simcal.rs:99) : `--num-predict 4294960000` →
      panic debug / wrap silencieux release (contexte tronqué à 896, exactement
      le mode que le flag devait empêcher). *Fix* : checked/saturating en u64.
- [ ] **M11 — `--min-delta` négatif/NaN casse l'élitisme.** Adoption rule
      `fit > best + delta` (llm.rs:249) : `--min-delta -1` fait adopter des
      **régressions** (contrat « aucune régression » violé, exit 0) ; `nan` →
      zéro adoption avec hint erroné « Ollama down ». *Fix* : `.filter(finite && >=0)`
      sinon exit 2 (miroir du `--max-seconds` déjà corrigé).
- [ ] **M12 — Un panic thread DGM tue tout le serveur MCP.** Verrou pris dans le
      thread (rsi_mcp.rs:438…) : panic sous lock → mutex empoisonné → le prochain
      `dgm_job::status()` panique sur le thread principal → serveur mort. Pas de
      `catch_unwind` nulle part ; panic entre locks → job « running » éternel.
      *Fix* : catch_unwind autour du corps du thread + `unwrap_or_else(into_inner)`.

### Crates scientifiques & packaging
- [ ] **M13 — Borne mathématiquement fausse.** `compare_after_optim_step`
      (cross_validate.rs:222-234) affirme `disp ≤ lr×clip×4` : ignore le weight
      decay (contre-exemple p=10000,wd=0.01 → disp≈10 ≫ 0.4) et la géométrie AdamW
      (~lr·√n par pas). Validateur exporté aux verdicts non fiables (faux positifs
      garantis si branché en gate). *Fix* : borne analytique correcte
      `lr·√n + lr·wd·‖θ‖`, ou ne garder que finitude+déterminisme.
- [ ] **M14 — Nix non reproductible.** Inputs `nixos-unstable`/flake-utils mutables,
      **aucun flake.lock committé** → chaque `nix build` résout un snapshot différent
      (rustc change de version selon le jour). Antinomique avec la posture
      P9/P10/`--locked`. *Fix* : `nix flake lock` + commit ; idéalement inputs épinglés par rev.
- [ ] **M15 — Fuzz nightly no-op dès la semaine 2.** Seed figée `Rng::new(0x5EED)`
      (json.rs:473) → les 5 M itérations du lundi sont identiques à la semaine 1 ;
      mode release sans debug-assertions/overflow-checks masque la classe
      arithmétique ; crash jamais imprimé/artefacté. *Fix* : seed via env (date),
      RUSTFLAGS debug-assertions, eprintln de l'échantillon fautif.
